## 開發方式

在 VISTA-World 的 `codex/vista-photoreal-design-r1` 分支與獨立 worktree 開發。起點是 R23 checkpoint `936d86d5`，沿用現有角色控制、動作交易、EventSpec 與串流介面。新版室內與資產另設 namespace；經過尺寸、碰撞、互動及畫面檢查後，再逐間整合。

這樣可以獨立重建視覺內容，也能保留現有互動成果與可比較的舊版本。不能直接沿用舊的隱藏碰撞盒：新模型的輪廓、門片厚度、握持點與碰撞必須一起對齊。

## 從圖片到 Blender／UE

1. **尺寸與布局先固定。** 平面配置以既有 `house.json` 的名義房間 bounds 及相鄰關係為起點，不是現場量測，也不是施工圖。淨尺寸、牆厚、窗洞及家具精確位置在新版 Blender 場景中確定。
2. **圖片決定外觀方向。** 圖片可用來選擇形狀、材質與生活細節；不同面板可能出現門窗、把手或比例差異。以 JSON 與單一 Blender 幾何模型解決矛盾，不能直接把生成圖當成可校準的攝影測量輸入。
3. **先建立同一份有尺寸的 Blender 場景。** 從這份場景輸出相同相機的多角度預覽，再以生成圖作外觀參照，逐步修正。每個模型保留可再執行的建模腳本。
4. **精細建模與材質分開處理。** 近看的物件要有真實壁厚、圓角、接縫、螺絲／鉚釘、內部結構；再建立獨立的 base color、normal、roughness、metallic 等材質資料。不能把帶光影的商品照直接當成完整 PBR 材質。
5. **可動零件拆開。** 鍋蓋、把手、冰箱門、抽屜等保留獨立部件、正確 pivot、開啟角度與握持／接觸點。UE 的碰撞、質量與動作目標另行設定。
6. **先完成廚房示範。** 一間廚房、三個核心物件、拿取／放置／開門；以同一組視角比较參考圖、Blender render 與 UE 實機。再將同一做法擴到其餘房間。

## 完成標準

目前完成標準是可檢查的設計參考包。後續「寫實可玩」的完成標準還包括：人眼高度近看成立、逆光與一般日光下材質成立、多角度形狀一致、角色可通過、門片不穿物、手部確實接觸、物件拿放不跳動，以及實測效能。圖片的寫實程度不代表這些 UE 行為已通過。

如需還原某一個真實現場或指定產品，還需要實際照片與尺寸；目前目標是原創且接近真實世界的住宅與日用品。
