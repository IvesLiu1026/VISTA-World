# 六空間還原盤點與研究案例（2026-09-14）

## 結論與證據邊界

六空間的原始任務尚未全部移植到目前的 Villa。舊 Home 地圖和原生資產仍在
Alpine 的 payload 中，因此可以沿用，無須把已存在的物件重做一次。

本次在獨立的 `villa-reference-avatar` 專案載入兩張原生地圖，讀取 GameMode、
actor labels 與 `Config/VistaHomeActions.json`，沒有修改地圖或執行互動。

| 檢查項目 | 保留的 Home | 目前 Villa |
| --- | --- | --- |
| 地圖 | `/Game/VISTA/PhotorealHomeR1/Maps/Home` | `/Game/VISTA/VillaR1/Maps/Villa` |
| GameMode | `HomeActionsGameMode` | `VistaVillaGameMode` |
| 地圖 actor 數量 | 190 | 213 |
| 原始合約 43 個具名實體的唯一 label 對應 | 43/43 | 0/43 |
| 另 3 個執行時 hazard | 此次未執行、不能據此判缺件 | 此次未執行 |
| 本機重跑原始任務全流程 | 尚未 | 尚未 |

Villa 有自己的水壺、水杯、水龍頭、花園門、移動等實作。0/43 表示原始 Home
合約不能直接綁定 Villa，**不代表 Villa 完全不能互動**。反過來，Home 的 43/43
也只證明物件仍在，不能當作本機 42 種動作已經跑過的證明。Manifest 中
`home_actions_bridge: true` 不是執行時驗收；已檢查的 Villa bridge 目錄沒有事件。

## 如何使案例支撐論文

每案用可檢查的初始狀態、允許的操作與目標條件定義，與
[BEHAVIOR 的任務條件做法](https://behavior.stanford.edu/getting_started/important_concepts.html)
相容；這個參考支持任務表示方式，不代表上述案例已有 BEHAVIOR 實作或具研究新穎性。

1. 每案至少有「風險存在／良性／已處理」三種版本，不能讓場景物件本身洩露答案。
2. 對同一初始狀態比較不介入、及時介入、較晚介入；其共同觀測前綴要驗證一致。
3. 模型只看到截止當下的影像／授權語音。口袋內容要靠先前可見操作或對話推斷，
   不將 actor label、隱藏狀態、種子、gold 或未來結果加入觀測。
4. 記錄判斷與介入時間、動作接受時間、實際生效時間、事件結果、誤介入與任務完成。
   以仿真時間計算物理量；另報實際 FPS，不把 fixed 30 Hz 當成 30 FPS 渲染。
5. 人物驗收包括手指抓握、腳底接觸、穿模、衣物／道具跟隨、轉身、停下及恢復動作。
   漂亮的外觀、腕部到達目標或預先剪好的影片都不能替代這些檢查。
