# 接近 GTA 操作質感的住宅：實作與驗收方向

2026-09-10。目標是近看人物、走動、操作物品時仍可信的即時 3D 場景。
目前 R5 與本次改動尚未達到這個整體品質；概念圖的逼真度不能當作 UE 成果。

## 從既有資產開始

目前有不同來源的環境，不能只依 Sunshine 名稱判定載入內容。

| 路線 | 已確認的資料 | 使用方式 |
| --- | --- | --- |
| 較早的 HSSD／City Sample 版本 | `hssd_r2_citysample_live_r1.json` 與舊版工具保留室內／人物來源；其 GTA、人物、碰撞及互動驗收欄位仍為 false | 先盤點實際場景、骨架、動畫與來源，再選取適用資產；尚未完成同相機實機比較 |
| 現有 Home R5 | 本次原生盤點 158 個靜態 mesh actor；MakeHuman 角色、同步的 owner/world body；沿用 R4 的 CC0 照片材質 | 保留可操作 demo；繼續沿用已驗證的動作 ID、手部接觸、相機與交易 |
| 新 Villa R1 工作副本 | 從 R5 複製的專案，另有設計圖、動作修改、近距離物件及液體校準工作 | 在獨立版本建立一個完整品質樣板，驗收後再擴充全屋 |

舊版部分資產／畫面保留 human-review-only 的使用範圍。這次只讀其程式與來源紀錄，沒有把受限人物或影格送入模型。可用來做研究模型輸入的資產，與只供人看的展示資產，必須照各自的紀錄選用。這不妨礙先完成可用資產的建模與材質工作。

## 最有效的改進順序

1. **人物與動作來源。**目前的角色頭髮輪廓、臉部與服裝仍像測試角色。升級高品質且適用的 rigged character、眼睛、頭髮與衣服，再建立一致的 locomotion clips。Motion Matching 可改善步行、轉向、停止之間的選片與銜接；抓握仍需專門手部姿勢、接觸及 IK。可參考 [Epic UE 5.7 Game Animation Sample](https://dev.epicgames.com/documentation/unreal-engine/game-animation-sample-project-in-unreal-engine?application_version=5.7) 和 [Groom rendering](https://dev.epicgames.com/documentation/unreal-engine/hair-rendering-and-simulation-in-unreal-engine)。它們是候選技術，尚未整套導入。
2. **一間完整廚房與一段操作。**先完成走到檯面、看向杯子、拿杯／壺、倒水、放回、視角切換。依序處理腳滑、肩肘姿勢、手指接觸、物件重量感與起止節奏。微小的呼吸／身體動作放在穩定接觸之後驗收。
3. **可近看的幾何與 PBR。**實際尺寸、圓角、杯口／壺壁厚度、底部、接縫和材質反射都要存在。照片 albedo、roughness、normal 必須有正確 UV 尺度與色彩空間。避免把照片直接貼在不相符的方塊上。新托盤／杯／玻璃壺是本次的材質與幾何樣板，還不是已接好所有操作的新道具。
4. **真實液體行為。**先在小範圍驗證 [UE Niagara Fluids 3D FLIP](https://dev.epicgames.com/documentation/en-us/unreal-engine/fluid-simulation-in-unreal-engine---overview) 的液面與障礙物反應，再做可關閉的水源、移動壺嘴、流入杯子與越過邊緣的溢水。現有 Home 的水柱、液面與 ml 狀態不能直接當作這些測試通過。
5. **二樓與全屋。**設計圖先確認風格；房間、樓梯、門窗和家具由同一份尺寸化 layout 建立。先驗證上下樓可走、落地／轉身自然、攝影機不穿牆，再擴充材質與陳設。二樓增加的遮擋也可服務長時觀察研究。

## 品質樣板的具體驗收

- 同一套資產在第一／第三人稱、室內照明和近距離檢查都成立；不能只用一張精選遠景。
- 空手、拿取、持物、放下和低頭都有實際身體表面；手指接觸前不吸附物品，手臂不伸長。
- 走、停、轉身、碰到障礙物時沒有明顯腳滑、穿模與突然跳姿；保留逐幀錄影與事件紀錄。
- 液體會在來源關閉後繼續運動；不能整個效果瞬間消失。碰撞、液量和溢出需各自測試，不能只看 Niagara 是否 active。
- 在記錄的解析度、GPU 與設定下量測 frame time 的中位數／p95。暫定先做到 1080p 穩定 30 fps，再改善至 60 fps；這是目標，尚非本次實測結果。
- 圖片生成與 Blender 預覽標示清楚；最終展示品質以 UE 實機及使用者操作為準。

## 如何接回 VISTA 與 EgoArgus

[VISTA](https://arxiv.org/html/2605.10579v2) 已提供可控制的情境生成與稽核；[EgoArgus](https://arxiv.org/html/2608.25561v1) 的 decision part 已使用 VISTA。因此新的研究不應只主張首次把兩者接起來。

可研究的是：在相同世界狀態下，畫面／對話證據的可靠度、助理提醒時機與人物反應，如何改變後續損失。例子是對話說「水已關」，但畫面仍有流水；比較沉默、及時與延遲提醒所造成的結果。這需要可還原的世界、真正執行的反應和可量測結果。高品質環境有助於消除明顯的視覺捷徑，但不等於研究有效性已獲證明。

本次保留 R5，先交付設計與實作基礎供審視。完整新人物、Motion Matching、所有液體與 Home 狀態的耦合、尺寸化二樓，以及研究閉環各有獨立驗收；不可把其中一項通過當作全部完成。
