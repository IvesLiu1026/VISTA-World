# 長時序、多事件的具身主動協助

研究問題：當一個人持續過日常生活，需求會出現、重疊、改變、甚至自行解除；助手如何從當下可見／可聽的線索判斷是否介入、先做什麼、何時中斷，以及之後接回哪件事？

暫定英文題目：**Knowing When to Interrupt: Priority-Aware Embodied Assistance in Continuous Egocentric Streams**。這是研究提案，沒有宣稱新穎性已確認或實驗已完成。

## 角色與視角

- 原本可操作人物是受協助的人（human），有自己的生活目標、通話、注意力和動作，不是 assistant。
- 旁邊的人形角色才是 embodied assistant。持續記住尚未完成的需求，必要時說話、移動和操作物件。
- 主設定是 **human ego video + 可聽音訊**。助手自己的攝影機是另外一種感測設定，必須分開評估，不能默默加入全屋資訊。第三人稱只做動作審查。
- 場景導演控制生活事件；評估器讀取世界真實狀態。兩者的未來時間表、seed、答案、deadline 真值及成功條件都不能送給助手。

## 與現有工作銜接

已讀 workspace 的 VISTA 2605.10579v2 與 EgoArgus 2608.25561v1 正式版本快照。
VISTA 提供 reactive / explicit proactive / implicit proactive，搭配 safety / inconvenience 與 no-assistance controls 的事件設計與審查方式。
EgoArgus 的重點是視覺與語言證據的一致、干擾與矛盾，以及需不需要幫、介入時間與 assist steps。
延續方式是讓同一個世界在介入後繼續演化，把單段判斷擴成有記憶、資源限制與結果回饋的連續協助。

研究定位還需要比較：

- [ProAssist（EMNLP 2025）](https://aclanthology.org/2025.emnlp-main.605/)：已有 streaming ego video 的主動對話；不能只以「長影片中主動說話」當作貢獻。
- [PARTNR（ICLR 2025）](https://arxiv.org/abs/2411.00081)：已有家居人機協作、空間／時間約束與 embodied planning；不能只以「多房間＋人與機器人」當作貢獻。

值得驗證的差異是：**無預告的新需求、多事件相互搶佔、打擾代價、解決後撤回提醒、被中斷任務恢復**，並且真正改變後續世界結果。這是由上述來源推導的研究方向，不是文獻缺口的定論。

## 一段生活，而非連續災難

先做 3–5 分鐘工程樣本，再擴成 15–30 分鐘研究 episode。目標時間尚未等於目前已驗證的運行長度。

| 空間 | 日常活動與必要物件 | 可重疊需求 | 不應介入的對照 |
|---|---|---|---|
| 玄關 | 穿鞋、拿鑰匙、帶包、開門 | 準備出門但東西還在別處 | 已拿好、只是在整理鞋子 |
| 客廳 | 接電話、看書、放杯子、看電視 | 忙著通話、杯子或物品擋路 | 正常談話、物品已移開 |
| 廚房餐廳 | 備餐、端杯、收拾、加熱 | 忘關爐火、拿著熱物又被叫走 | 正常烹調、已關火、只是燈光反射 |
| 臥室 | 起床、拿手機、整理衣服 | 尋找物品與來電重疊 | 聽電話本身不表示需要協助 |
| 書房 | 用電腦、找文件、取高處箱子 | 不穩定支撐、重要工作被打斷 | 已採用穩定梯具 |
| 浴室洗衣區 | 放水、洗衣、放毛巾 | 水位持續上升、稍後才需取衣 | 正常低水位、已關水、尚未洗完 |

上述是情境候選，不代表每一項已實作。優先增加有動作／觀察用途的物件，而不是用雜物填滿畫面。

示範順序：人提到要出門 → 做日常事 → 接電話 → 已觀察到的低優先需求保留待辦 → 另一處出現可觀察的急迫線索 → 助手插話或中斷自己的次要工作 → 確認解除 → 通話結束後接回原任務。正常與自行解決的區段也必須保留。

## 系統要怎麼做

1. **持續世界**：事件獨立生命週期、共同 simulation clock，不因換事件而 ResetScene。初始寫入先完整驗證；手上物品、人物位置、物件狀態與其他事件的時間保留。
2. **可觀察串流**：影像與音訊各有 acquisition timestamp、可用時間與延遲；按過去到現在處理。第一版可見物件／線索的 engine adapter 是工程基線，正式感知實驗另用 RGB/audio。
3. **事件記憶**：存目前證據、來源、最後確認時間、推測需求、進度、不確定性和人是否已自行處理。離開視野不能當作「已解決」。
4. **優先與插話**：判斷後果嚴重度、發生機率、估計時間餘裕、行動耗時、人的注意力、打擾代價和自身能力。時間餘裕要扣掉導航、操作與模型延遲；不能永遠寫死「水 > 火 > 鑰匙」。
5. **可中斷執行**：記錄動作開始、接觸、承諾點、可安全中止階段和資源占用（左右手、位置、人物）。緊急時先短提醒；較慢的長計畫可在之後更新。被搶佔的任務保留，不用重新問人。
6. **結果確認**：說出建議不等於完成。透過新畫面／可聽回饋判斷，必要時接近觀察；拒絕、不確定、路被擋也都是有效結果。

人物優先做停走／轉身、視線先行、自然呼吸眨眼、手持電話抬起與放下、聽／說的交替、拿放的手指接觸、讓路。皮膚、眼睛、頭髮、衣服需要同時符合近景、光照和動畫；單提高貼圖解析度不會解決姿態。

## 可以投稿的核心實驗

- **RQ1：多事件干擾**。固定底層事件，改變重疊數 1 / 2 / 3、時間間隔、可見性與干擾對話，測漏掉急事、錯誤打擾和任務恢復。
- **RQ2：證據矛盾與過時記憶**。人說「已經關掉」但新畫面不同；或之前看到問題、後來人已自行解決。比較 video only / audio-text only / combined 與不同記憶策略。
- **RQ3：有限運算下的反應**。比較每個固定時刻都呼叫大模型、事件觸發小模型、分層快速提醒＋較慢重規劃。實測 wall-clock latency、tokens、VRAM 與錯誤，不以 GPU 利用率替代反應時間。

基線：不協助、固定週期提醒、FIFO、有記憶的規則優先佇列、LLM/VLM 單層規劃、分層／可搶佔規劃。特權 oracle 僅作不同資訊條件的上界，不能當公平模型比較。

指標包括最早可觀察線索到決策／語音／實際動作的延遲（分段報告 p50/p95）、急事漏失、無需求時每小時打擾次數、resolved-event 誤提醒、priority inversions、實際完成率、搶佔後恢復率、碰撞／不可行動作和運算量。Deadline miss 須用作者／人審真值衡量，不能用模型猜測作答案。

train/dev/test 按事件模板、布局及事件組合切分；同一 seed 的時間抖動不可跨 split。安排正常／已解決對照，避免場景或物件直接洩漏 assistance label。多個 seed、置信區間與失敗案例一併報告。

介入／不介入的因果比較，需要固定初始條件與外生排程、讓內生結果隨行動改變；單次腳本演示或不同場景的影片不是反事實評估。現有液面、爐火與超時部分是程序式狀態／視覺模型，不能當作真實熱力學或水動力學驗證。

## 本次工程切片的邊界

原始版本只有單一 event，StartEvent 會重置所有物件；目前來源新增不重置的並發路徑，舊操作保留。新資料限 development copy。
導演用人工腳本操作 **human**，旁邊的 embodied companion 依規則基線給短語音提醒。這不等於 assistant 已能自主導航操作爐具、也沒有 image VLM／ASR；對話文字回放明確標記 authored transcript。
初版人物臉沿用既有 53 骨架與新 morph mesh，加入眨眼與由實際播放音訊驅動的近似嘴型。這不是 motion capture 或 phoneme alignment。
原生錄影是工程檢查影片，包含人工導演使用的 console 與 review HUD；不可直接當成無洩漏的模型 RGB 輸入。本次規則程式只收到獨立的 observation 與明確標記的文字回放，但尚未建立作業系統層級的感知隔離。
新增居家道具中有些只提供 inspect；只對實際驗證的拿放宣稱可操作。外部材質與角色資產仍需逐項確認研究／再散布範圍，當前演示不會自動成為可公開 benchmark。
